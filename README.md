# beacon

A small FastAPI service that exercises the whole OKD platform path:

```
GitHub ──push──▶ GitHub Actions ──build──▶ GHCR
   ▲                    │ bumps image tag in deploy/overlays/okd
   └────────────────────┘
                 Argo CD (watches the repo) ──sync──▶ OKD namespace "beacon"
                                                        │
  ┌──────────── pod (ServiceAccount "beacon") ──────────┴─────────────┐
  │ projected SA token (aud=vault) ─▶ Vault k8s auth ─▶ secret/beacon/config
  │ db_username/db_password from Vault ─▶ PG4K cluster  (schema "beacon")
  │ /metrics ─▶ ServiceMonitor ─▶ user-workload Prometheus ─▶ Grafana
  │ JSON logs on stdout ─▶ log collector ─▶ Loki ─▶ Grafana (errors panel)
  └────────────────────────────────────────────────────────────────────┘
```

| Requirement | Where |
|---|---|
| Secret from Vault via a ServiceAccount | `app/vault_client.py`, `vault/setup-vault.sh`, projected token in `deploy/base/deployment.yaml` |
| DB schema on PG4K | `deploy/postgres/` (Database CR + managed role), `migrations/*.sql` applied by the `beacon-migrate` Sync-hook Job |
| Metrics: version, pod count/status, health | `app/metrics.py`, `deploy/base/servicemonitor.yaml`, `deploy/base/prometheusrule.yaml` |
| Logs, errors in Grafana | `app/logging_setup.py` (JSON, one ERROR line per real error, stack + request_id) |
| Grafana | `grafana/beacon-dashboard.json` (generated by `grafana/build_dashboard.py`) |
| GitOps | `argocd/root-app.yaml` → `argocd/apps/*` ; CI in `.github/workflows/ci.yaml` |

## 1. Make it yours

```bash
# your GitHub user/org (lower case), then commit
grep -rl OWNER . --exclude-dir=.git | xargs sed -i 's/OWNER/your-github-user/g'
```

Then edit the values marked `# <--`:

| Value | File(s) | Default |
|---|---|---|
| Vault address | `deploy/overlays/okd/kustomization.yaml` | `https://vault.example.com:8200` |
| PG4K cluster name / namespace | `deploy/postgres/*.yaml`, overlay `DB_HOST`, `argocd/apps/beacon-db.yaml` | `pg-main` / `postgres` |
| Argo CD namespace | `argocd/**` | `openshift-gitops` |
| Grafana namespace + instance label | `grafana/kustomization.yaml`, `grafana/grafanadashboard.yaml`, `argocd/apps/beacon-dashboard.yaml` | `grafana`, `dashboards: grafana` |
| SNO? | overlay: uncomment the 1-replica patch | 2 replicas |

If Vault uses a private CA, add `VAULT_CACERT: /etc/vault-ca/ca.crt` to the ConfigMap and mount the CA ConfigMap there.

## 2. Cluster prerequisites (once)

```bash
# User-workload monitoring (ServiceMonitor / PrometheusRule in your namespaces)
oc -n openshift-monitoring get cm cluster-monitoring-config -o yaml | grep enableUserWorkload
# if missing:
oc apply -f - <<'EOF'
apiVersion: v1
kind: ConfigMap
metadata: {name: cluster-monitoring-config, namespace: openshift-monitoring}
data:
  config.yaml: |
    enableUserWorkload: true
EOF
```

Logs: anything that ships container stdout to Loki works (OpenShift Logging + LokiStack, or Promtail/Alloy). The dashboard has a **Loki namespace label** switch: `kubernetes_namespace_name` (OpenShift Logging) or `namespace` (Promtail/Alloy). The error filter matches both raw JSON and OpenShift Logging's wrapped `message` field.

Grafana: needs a Prometheus datasource on the **Thanos querier** (so kube-state-metrics pod phase/restarts are visible) and a Loki datasource. `grafana/datasources-okd.example.yaml` shows both for grafana-operator.

## 3. Vault + database bootstrap (once)

```bash
export VAULT_ADDR=https://vault.example.com:8200 VAULT_TOKEN=<admin token>
oc login ...   # cluster-admin
PG_NS=postgres PG_CLUSTER=pg-main ./vault/setup-vault.sh
```

This is idempotent and:

1. creates a `vault-auth` token-reviewer SA (`system:auth-delegator`) for Vault running outside the cluster;
2. enables/configures `auth/kubernetes` against your OKD API;
3. writes policy `beacon` (read-only on `secret/data/beacon/config`) and role `beacon` bound to **SA `beacon` in namespace `beacon`, audience `vault`**;
4. writes the secret (`db_username`, `db_password`, `db_host`, `db_name`, `greeting`);
5. mirrors the DB password into Secret `beacon-db-password` in the PG4K namespace.

Then add the managed role to your PG4K `Cluster` (see `deploy/postgres/README.md`).

## 4. Deploy with Argo CD

```bash
git push origin main              # CI builds ghcr.io/<you>/beacon and bumps the overlay
oc apply -f argocd/root-app.yaml  # once
```

Sync order: `beacon-db` (Database CR) → `beacon`: SA + ConfigMap (wave -1) → **migrate Job** (Sync hook, wave 0; must succeed) → Deployment, Service, Route, ServiceMonitor, PrometheusRule (wave 1).

**Image pull:** GHCR packages start private. Either make the package public (GitHub → Packages → beacon → settings), or:

```bash
oc -n beacon create secret docker-registry ghcr-pull --docker-server=ghcr.io \
  --docker-username=<you> --docker-password=<PAT with read:packages>
```

and uncomment `imagePullSecrets` in `deploy/base/serviceaccount.yaml`. Disconnected cluster? Mirror the image and change `newName` in the overlay.

## 5. Check it

```bash
H=$(oc -n beacon get route beacon -o jsonpath='{.spec.host}')
curl -s https://$H/health | jq            # versions, vault + db status, schema version
curl -s https://$H/api/secret-info | jq   # proves the Vault read (key names + version only)
curl -s -XPOST https://$H/api/items -H 'content-type: application/json' -d '{"name":"hello"}'
curl -s -XPOST https://$H/api/simulate-error          # -> ERROR log + beacon_errors_total
oc -n beacon logs job/beacon-migrate
```

Import `grafana/beacon-dashboard.json` (or let the `beacon-dashboard` app do it). Generate a few errors and they appear in **App errors**, **ERROR log lines** and the **Errors** log panel within ~30 s.

## Endpoints

| Path | Purpose |
|---|---|
| `/healthz/live` | liveness (process up) |
| `/healthz/ready` | readiness: Vault secret loaded **and** DB reachable (503 otherwise) |
| `/health` | detail JSON |
| `/metrics` | Prometheus |
| `/api/items` | GET list / POST create (DB) |
| `/api/secret-info` | Vault secret key names + version |
| `/api/simulate-error?kind=runtime\|handled` | test errors (disable with `ENABLE_CHAOS_ENDPOINTS=false`) |

## Metrics

| Metric | Use |
|---|---|
| `beacon_build_info{version,commit}` | version per pod; `count(...)` = pods running |
| `beacon_up`, `beacon_health_status{component}` | app health; vault / database |
| `beacon_http_requests_total`, `_request_duration_seconds` | traffic, 5xx, latency |
| `beacon_errors_total{type}` | every logged error, by type |
| `beacon_vault_*` | logins, reads, secret version, token TTL, last success |
| `beacon_db_*`, `beacon_items` | query latency, pool, schema version, row count |
| kube-state-metrics | `kube_pod_status_phase`, restarts, desired/available replicas |

Alerts (`prometheusrule.yaml`): no ready pods, dependency unhealthy, replicas unavailable, restarts, mixed versions > 30 min, 5xx > 5 %, error bursts, stale Vault secret.

## Rotating the secret

```bash
DB_PASSWORD="$(openssl rand -base64 24)" ./vault/setup-vault.sh
```

PG4K reloads the role password from the labelled Secret; each pod sees the new KV version within `SECRET_REFRESH_SECONDS` (300 s), logs `database credentials rotated` and swaps its connection pool. No restart needed.

## Local development

```bash
pip install -r requirements-dev.txt && pytest -q && ruff check .
# against a dev Vault + local Postgres:
VAULT_ADDR=http://127.0.0.1:8200 VAULT_DEV_TOKEN=root DB_SSLMODE=disable \
  uvicorn app.main:app --reload --port 8080
python grafana/build_dashboard.py   # after editing the dashboard
```

Release: bump `VERSION`; images are tagged `<VERSION>-<sha7>`, `<VERSION>` and `latest`.
